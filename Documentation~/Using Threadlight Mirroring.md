# Using ThreadLight Mirroring

ThreadLight Mirroring creates and maintains the Live Mirroring setup stored
with a prefab. It is intended for constraint targets that need a mirrored
source/target relationship, shared prefab scaling, and editor-only scene
preview ghosts.

## Before you begin

VCC installs the required ThreadLight Authoring package with Live Mirroring
Builder. The Builder will not replace the prefab root, existing children, or
creator-authored transforms. ThreadLight Components is installed separately by
customers who receive a finished prefab; it is not required for authoring.

Open **Tools > ThreadLight > Mirroring**. ThreadLight Authoring is
the only WolfyVR package dependency required to create a setup.

## Create a setup

1. Choose the prefab root in **Prefab Root**, or select it in the Hierarchy and
   use **Use Selection**.
2. Optionally choose **Prefab Scale Reference**. This must be inside the
   selected root. Leave it empty to have Build create an owned `Prefab
   Container` for shared scaling.
3. Select **Create & Build** in the bottom dock.

Build creates the editor-only setup holder and generated constraint targets. It
does not replace existing prefab content. Unity Undo can restore the setup
immediately after creation or a later build.

## ThreadLight Mirroring Setup

Use **ThreadLight Mirroring Setup** to choose an existing setup. Use
**Select Setup Object** to find its editor-only holder in the Hierarchy.

When creating a new setup, **Prefab Root** is the prefab that will own it.
**Use Selection** fills this field from the active Hierarchy selection.

## Target Naming & Organization

**Constraint Targets Object Name** controls the name of the generated targets
holder. The target cards below it define each source/mirrored relationship.
The prefix, R/L labels, source and mirrored folder names, transform defaults,
and unused-target cleanup use the same model as the full ThreadLight Builder.

- **+ Add Target** adds an empty source/mirrored pair.
- **Add Selected Objects** creates a new pair from exactly two selected
  transforms. Select the source first and the intended opposite-side target
  second; the builder fills both fields for you.

Each target card has its own controls:

- **Create Opposite Target** keeps a second-side target. While Live Mirroring
  is enabled, that target follows its source automatically.
- **Use Global Side Labels** uses the shared R/L labels; turn it off to provide
  labels for this target only.
- **Target Name** is the label used in the Builder.
- **Source** is the transform that drives the pair. Leave it empty to have
  Build generate an empty target.
- **Mirrored Target** receives the mirrored transform. Leave it empty to have
  Build generate one.
- **Source Bone** and **Mirrored Bone** appear when VRCFury armature links are
  enabled.
- **Rotation Offset** adds a local rotation after the mirrored transform is
  calculated.
- **Up**, **Down**, **Swap**, and **Remove** reorder, exchange, or remove that
  pair from the setup.

Choose **Build Setup** after changing pairs. It updates generated targets while
preserving creator-authored content it does not own.

## Target Defaults & Preview Helpers

This section controls generated target helpers and shared scaling.

- **Add VRCFury Armature Links** adds or updates VRCFury Armature Link
  components on targets generated by the Builder when VRCFury is installed.
- **Synchronize Scale** keeps generated constraint targets at the same shared
  world scale as the prefab scale reference. Keep it enabled for constraint
  targets.
- **Prefab Scale Reference** identifies the object used as that scale basis.
- **Add Parent Constraint To Prefab Container** adds a VRC Parent Constraint
  to that object and assigns every configured source and mirrored target.
- **Additional Scale Handles** adds other transforms that need the same scale
  treatment.

The builder rejects an invalid scale reference instead of silently moving it.
When no reference is set, its owned `Prefab Container` makes the scale
topology explicit and safe.

## Live Mirroring

This section controls the live relationship between each enabled source and
mirrored target.

- **Live Mirroring** turns continuous editor-time mirroring on or off.
- **Mirror Center** is the transform whose position and orientation define the
  mirror plane.
- **Mirror Axis** chooses which local axis of the mirror center separates the
  two sides.
- **Mirror Position**, **Mirror Rotation**, and **Mirror Scale** choose which
  parts of the source transform are applied to the mirrored target.

## Mirroring and Scaling

Use the **Live Mirroring** card to decide what is mirrored, then use **Target
Defaults & Preview Helpers** to keep the generated targets at the intended
shared scale. Enable **Mirror Scale** only when the source object's local scale
should be copied to the mirrored target. **Synchronize Scale** is separate: it
keeps the constraint target system aligned with the prefab scale reference.

## Scene preview

The **Scene Preview** section controls editor-only preview ghosts.

- **Show Scene Preview** enables or disables the preview.
- **Preview Source** chooses the object drawn by the preview.
- **Preview Material** controls its appearance. Build prefers the included
  Ghost Material when none is selected and falls back to Unity's default.

Preview helpers are editor-only authoring state. They are not intended to be
part of the uploaded avatar.

## Build, validate, and undo

The bottom dock always explains whether it will create or update a setup.
Correct validation messages before building. Common causes are selecting a
root outside Prefab Mode, a scale reference outside the prefab root, duplicate
or cyclic target relationships, or a root managed by another Builder.

If a prefab root is managed by the full ThreadLight Builder, ThreadLight Mirroring
will show that ownership and direct you to edit it there. Do not try to keep
two tools synchronised; import or build from the authoritative tool for that
prefab.

After building, inspect the generated targets and scene preview, then use
Unity Undo if the result is not what you expected. For a final avatar check,
test in Play Mode and through the normal VRChat build/upload workflow.
